# 김리라 포트폴리오 사이트

정적 HTML 3페이지. 빌드 도구 없이 파일을 그대로 열면 동작합니다.

```
index.html      메인 — 헤드라인 · 21개 날씨 상태 그래픽 · 지표 · 강점 · 대표 프로젝트
resume.html     이력서 — 인쇄(PDF 저장) 스타일 포함
projects.html   프로젝트 — 태그 필터 + 펼침형 상세
assets/site.css 공통 스타일 (컬러·타입 토큰이 :root 에 정리되어 있음)
assets/site.js  GNB 자동 숨김, 프로젝트 렌더·필터
data/projects.js 프로젝트 데이터  ← 여기만 고치면 됩니다
files/          첨부용 PDF (이력서·포트폴리오)
```

프로젝트 목록은 **프로젝트 페이지와 이력서 Experience 두 곳에서 같은 데이터**를 씁니다.
`data/projects.js` 하나만 고치면 양쪽이 동시에 갱신됩니다.

## 필터

회사 · 태그 2단이고 두 조건이 함께 적용됩니다(AND).
- **회사**는 `service` 값의 `·` 앞부분에서 자동으로 뽑습니다. `'Tnear · 첫화면날씨'` → `Tnear`
  새 회사를 쓰면 칩이 자동 생성되므로 따로 적을 필요가 없습니다.
- 한쪽을 고르면 다른 쪽 칩의 개수가 다시 계산되고, 0건인 칩은 비활성됩니다.

## 첨부 PDF

`files/` 안의 파일을 링크로 내려받게 되어 있습니다. 파일을 새 버전으로 덮어쓰면 링크는 그대로 유지됩니다.

| 위치 | 파일 |
|---|---|
| 이력서 페이지 상단 `이력서 PDF ↓` | `files/김리라_이력서.pdf` |

## 프로젝트 추가하기

`data/projects.js` 의 배열 **맨 위**에 객체를 하나 추가하면 프로젝트 페이지에 바로 나타납니다.
`featured: true` 를 넣으면 메인 페이지 대표 프로젝트 카드에도 함께 노출됩니다.

```js
{
  id: 'my-project',                 // 필수 · 영문 소문자, 링크 앵커로 쓰입니다
  title: '프로젝트 이름',            // 필수
  service: '회사 · 서비스명',        // 카드 상단 파란 라벨
  period: '2026.01 – 2026.03',      // 필수
  tags: ['UX 개선', '데이터'],       // 필수 · 필터 칩이 자동 생성됩니다
  summary: '한 줄 요약.',            // 필수 · 목록에 접힌 상태로 보이는 문장
  problem: '무엇을 문제로 정의했는지.',
  approach: ['한 일 1', '한 일 2'],
  metrics: [{ val: '+28%', lab: '위젯 DAU' }],
  note: '회고나 아쉬웠던 점.',        // 있으면 '회고' 블록으로 노출
  role: 'Planning 50% / UX·UI Design 100%',
  featured: true,                   // 메인 노출 여부
  link: 'https://...'               // 상세 케이스 스터디가 따로 있으면
}
```

필수는 `id · title · period · tags · summary` 뿐이고, 나머지는 없으면 그 블록이 생략됩니다.

## 색을 바꾸려면

`assets/site.css` 맨 위 `:root` 의 값만 바꾸면 전체에 반영됩니다.
`--blue` 는 구조·내비게이션, `--amber` 는 지표(변화량)에만 씁니다. 이 역할 구분을 유지하면 톤이 흐트러지지 않습니다.

메인의 날씨 상태 21개 컬러는 `assets/site.js` 의 `WEATHER_STATES` 배열에 있습니다.
실제 디자인 시스템의 컬러 값이 있다면 `c` 값만 바꿔 넣으면 됩니다.
